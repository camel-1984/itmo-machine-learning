# Jupyter Notebook

## Что это

Интерактивная среда: код разбит на ячейки, результат каждой показывается прямо под ней.

- `.ipynb` - файл ноутбука, внутри JSON: код + результаты + метаданные.
- **kernel** - процесс Python, который выполняет код.
- **клиент** - интерфейс: JupyterLab, VS Code, PyCharm, Colab, Kaggle.

## Как работает

Скрипт запустился, отработал и умер - переменные исчезли. Kernel живёт между запусками ячеек, переменные остаются в памяти. Поэтому данные читаются один раз, а ячейку с графиком можно перезапускать сколько угодно.

Ячейки выполняются в любом порядке. Типы: code и markdown.

## Вывод

- Значение последнего выражения ячейки выводится само, DataFrame - таблицей.
- Вывести что-то из середины ячейки или несколько таблиц подряд - `display(df)`. `print` выводит DataFrame голым текстом.
- Графики появляются под ячейкой сами, `plt.show()` не нужен.
- Показать все колонки: `pd.set_option("display.max_columns", None)`.

## Скрытое состояние

Удалил ячейку - переменная из неё осталась в памяти. Ноутбук работает у тебя и падает у другого. Лечится: Restart + Run All. Прошло сверху вниз без ошибок - ноутбук честный.

## Ячейка или модуль

- **В ячейке** - разведка, одноразовый код, короткие шаги, параметры графиков.
- **В `.py`** - код повторился второй раз, логика устоялась, нужны тесты или импорт из других мест. В ячейке остаётся вызов.

Изменил модуль - нужно перезапустить kernel. Или в первой ячейке:

```python
%load_ext autoreload
%autoreload 2
```

Тогда изменения в `.py` подхватываются сами.

## Типовая раскладка

1. Импорты, загрузка данных, приведение типов.
2. Проверки: `df.dtypes`, `df.head()`, `value_counts()`.
3. Вызов функций подготовки из модуля.
4. Графики - перезапускаешь только их.

## Git

`.ipynb` плохо ложится в git: код и результаты в одном JSON, diff нечитаемый. Ещё одна причина держать логику в модулях.
