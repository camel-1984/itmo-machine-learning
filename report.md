## 1. Задача и критерии качества

### 1.1 Контекст

Система раннего предупреждения получает поток измерений сети сейсмостанций и должна заранее сообщить целевой станции, что к ней придёт сильная тряска (0.01 g и выше). Собственные измерения цели недоступны, решение принимается только по восьми соседям. Ценность предупреждения определяется запасом времени: меньше 3 с недостаточно для автоматических действий (остановка лифтов и поездов, перевод оборудования в безопасный режим), поэтому такое предупреждение считается бесполезным.

Действующие системы (ShakeAlert в США, JMA в Японии) решают задачу иначе: по плотной сети оценивают очаг и магнитуду и пересчитывают их в прогноз тряски по формулам затухания. Здесь данных для такого подхода нет (несколько десятков землетрясений, 8 соседей на цель), поэтому задача ставится как прямая классификация по соседям. Трудности у действующих систем те же: слепая зона около очага и рой афтершоков. На той же серии Ridgecrest, из которой взяты наши данные, ShakeAlert недооценил магнитуду главного толчка M7.1, и самый пострадавший район предупреждения не получил ([разбор USGS](https://www.usgs.gov/publications/shakealert-earthquake-early-warning-system-performance-during-2019-ridgecrest)).

### 1.2 Объект решения и исходы

Случай - пара «целевая станция × момент срабатывания»: на одном из соседей односекундная амплитуда впервые достигла 0.001 g. Дальше каждую секунду (`t = 0..30`) приходит строка с измерениями соседей, после каждой строки система выдаёт оценку `s_t ∈ [0, 1]`. Предупреждение отправляется в момент `a = min{t : s_t ≥ threshold}`, не более одного раза на случай.

`T` - время от открытия случая до первого достижения 0.01 g на цели (`onset_after_trigger_s`, только для `label = 1`, до 45 с). Предупреждение своевременно при `a ≤ T - 3`.

| Условие | Исход |
|---|---|
| `label = 1`, `T ≥ 3`, `a ≤ T - 3` | своевременное (TP) |
| `label = 1`, `T ≥ 3`, `a > T - 3` | позднее |
| `label = 1`, `T ≥ 3`, предупреждения нет | пропуск |
| `label = 1`, `T < 3` | слепая зона: успеть невозможно при любом решении |
| `label = 0`, предупреждение есть | ложное (FA) |
| `label = 0`, предупреждения нет | верное молчание |

Позднее предупреждение и пропуск для пользователя равноценны: тряска приходит без запаса времени. Ложное предупреждение дешевле, но в эксплуатации воспринимается как частота во времени. `T` дробное, `a` целое: при `T = 8.35` своевременны `a ≤ 5`. Задержка передачи в данных не моделируется, вычислительная задержка оценивается отдельно (п. 6.1).

### 1.3 Формулировка ML-задачи

| Вариант | Суть | Решение |
|---|---|---|
| классификация случая по фиксированному началу `t ≤ k` | один прогноз на случай | нет: фиксирует момент предупреждения и не даёт компромисса между ранним и точным |
| регрессия или survival-модель `T` | прогноз времени начала тряски | нет: 183 положительных с `T ≥ 3`, цензурирование на 45 с усложняет постановку без явной выгоды |
| **построчная классификация «предупреждение сейчас будет своевременным» + порог** | модель оценивает строку, политика - первое пересечение порога | **выбран**: порог напрямую задаёт компромисс TR / FA |

Целевая переменная строки: `y_t = 1`, если `label = 1` и `t ≤ T - 3`; `y_t = 0` для всех строк `label = 0`. Строки положительных случаев после дедлайна (и все строки слепой зоны) исключаются из обучения. Альтернативы хуже: `y_t = 0` противоречит факту тряски в момент, когда сигнал у соседей самый сильный, а `y_t = 1` учит модель именно поздним предупреждениям. Исход таких случаев к этому моменту уже определён, поэтому исключение не влияет на метрику.

### 1.4 Метрики

Основные метрики, по ним выбираются модель и порог:

| Метрика | Определение | Данные |
|---|---|---|
| Timely recall, TR | `TP / P₃`, `P₃` - положительные с `T ≥ 3` | события и поток, отдельно и вместе |
| FA rate | ложные предупреждения / `Σ station_hours` | поток |

FA считается на станцио-час, а не как доля от отрицательных случаев. Доля отрицательных в наборе определяется отбором интервалов, а станцио-часы включают и тихие интервалы, где срабатывания не было вообще.

Слепая зона исключена из знаменателя TR: своевременное предупреждение там невозможно, и её доля сильно различается между частями (36 из 219 положительных на train, 26 из 47 на test). Покрытие с учётом слепой зоны показано отдельно как system recall = `TP / P`.

| Дополнительная метрика | Назначение |
|---|---|
| запас `T - a` у TP: медиана | ценность своевременного предупреждения |
| число поздних и пропусков отдельно | позднее - модель видит событие, но медленно; пропуск - не видит |
| доля ложных среди отрицательных событийной части | в событиях станцио-часов нет, отрицательные рядом с землетрясениями труднее потоковых |
| TR по корзинам `T`: 3-6, 6-15, 15-30, ≥ 30 с | быстрые случаи требуют решения на первых секундах |
| TR на группе главного толчка M7.1 отдельно | режим сильного землетрясения |
| partial AUC кривой TR - FA на FA ∈ [0, 1] | сравнение моделей без фиксации порога |

Не используются: accuracy (82-91% отрицательных), построчные F1 и ROC-AUC (31 зависимая строка на случай, не учитывают правило первого предупреждения), F1 и ROC-AUC по максимальной оценке случая (не учитывают своевременность).

### 1.5 Принцип выбора рабочей точки

Численных стоимостей ошибок нет. Есть два эквивалентных способа выбрать точку: цена (`U = TP - λ·FA`, «пропуск стоит λ ложных») или ограничение (максимум TR при `FA ≤ B`); каждому `B` соответствует своё `λ`. Выбрано ограничение, потому что бюджет ложных тревог проще согласовать с потребителем. Значение `B` выбирается по форме OOF-кривой: точка, после которой каждое дополнительное своевременное предупреждение стоит непропорционально много ложных (п. 4.3). Основным результатом считается вся кривая, точка на ней - решение для конкретного применения.

### 1.6 Ограничения

| Ограничение | Следствие для решения |
|---|---|
| решение на шаге `t` только по строкам `0..t`, без полей ответов | признаки текущей строки, проверка префиксом случая |
| одно предупреждение на случай, строки разных случаев приходят вперемешку | состояние хранится отдельно по `candidate_id` |
| шаг данных 1 с | обработка строки должна укладываться в миллисекунды |
| только классические модели, без нейросетей и внешних данных | ансамбль деревьев |
| все решения только по train | test - одна финальная проверка зафиксированной системы |

### 2.5 Группы и фолды

Правило групп: случай потока - его `window_id`. Событийный случай относится к активному интервалу потока, если время землетрясения попадает в `[start - 60 с, end]` этого интервала, вместе со всей своей `sequence_group` (так объединено 12 серий); иначе группа - его `sequence_group`. Итог - 40 групп.

| Схема | Проблема | Решение |
|---|---|---|
| KFold по строкам или случаям | утечка по всем пунктам 2.4 | нет |
| forward chaining по времени | 58% положительных в одной группе за 2019-07-06, содержательных фолдов 1-2 | нет |
| leave-one-group-out | 40 обучений, 16 фолдов без положительных, разброс по фолдам не интерпретируется | нет |
| **StratifiedGroupKFold(5) по общим группам** | M7.1 целиком в одном фолде | **выбрана**, фолд M7.1 анализируется отдельно |

Параметры: `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)`, стратификация по `label` случая.

| Фолд | Групп | Случаев | Можно успеть | M7.1 |
|---|---|---|---|---|
| 0 | 1 | 447 | 110 | да |
| 1 | 11 | 263 | 11 | нет |
| 2 | 10 | 251 | 17 | нет |
| 3 | 7 | 251 | 26 | нет |
| 4 | 11 | 264 | 19 | нет |

Проверки разбиения: случаев в двух группах, разорванных интервалов, разорванных серий, событий вне своего интервала, групп в двух фолдах - 0.

Почему оценка переносится на более поздние данные: в проверочном фолде всегда землетрясения, которых не было в обучении, как и в test; сеть и расстояния те же; test - более поздние афтершоки той же серии. Порядок по времени внутри train не соблюдается, это допустимо: распространение волн и сеть за этот период не меняются. Фолд M7.1 дополнительно показывает работу на сильном землетрясении, которого модель не видела.

## 3. Baseline и обучение

### 3.1 Baseline

Правило без обучения: оценка строки - максимальная амплитуда `rms1` среди соседей, порог подбирается тем же способом, что и для моделей. Это нижняя планка: если модель её не превосходит, ML не нужен.

| Метрика (OOF train) | FA ≤ 0.3 | FA ≤ 0.5 | FA ≤ 1.0 |
|---|---|---|---|
| TR правила | 0.186 | 0.284 (52 из 183) | 0.388 |

### 3.2 Признаки и недоступность станций

11 признаков текущей строки. Соседи сортируются по расстоянию до цели, недоступная станция получает бесконечное расстояние и уходит в конец сортировки, поэтому «ближайший» и «три ближайших» берутся из доступных станций, а максимумы, средние и счётчики считаются только по доступным. В признаках нет пропусков, и отдельной логики для недоступности не требуется: на 46 случаях потокового test без одной станции система работает тем же кодом.

| Признак | Смысл |
|---|---|
| `t_sec` | возраст случая |
| `log_max_rms1`, `log_max_rms3` | максимум амплитуды соседей за 1 и 3 с |
| `log_mean_rms1` | средняя амплитуда по соседям |
| `log_nearest_rms1` | амплитуда ближайшего доступного соседа |
| `log_near3_max_rms1` | максимум по трём ближайшим доступным |
| `log_max_rms1_per_km` | максимум амплитуды, делённой на расстояние до цели: сильно и близко |
| `n_above_gate`, `n_above_strong` | число соседей выше 0.001 g и 0.01 g |
| `loudest_km`, `nearest_km` | расстояние до самого трясущегося и до ближайшего соседа |

### 3.3 Веса случаев

У каждого случая суммарный вес 1, поровну между его обучающими строками. Без весов случай с `T ≥ 33` даёт до 31 положительной строки, а случай с `T` 3-6 с - одну-три, хотя в TR оба весят одинаково, и обучение подстраивается под медленные случаи. Балансировка классов эту проблему не решает: перекос внутри положительного класса, а не между классами. Веса добавили своевременные предупреждения в основном на быстрых случаях.

### 3.4 Модели и ансамбль

| Вариант | Решение | Причина |
|---|---|---|
| одно дерево решений | нет | мало различных значений оценки, кривая порога слишком грубая |
| HistGradientBoosting | нет | на сырых признаках то же качество, что CatBoost |
| **CatBoost** | **да** | бустинг: деревья строятся последовательно и исправляют ошибки предыдущих, сильная модель на табличных данных |
| **RandomForest** | **да** | бэггинг: много независимых деревьев усредняются, меньше разброс; другой тип ошибок для ансамбля |
| **мягкое голосование (среднее вероятностей)** | **да** | простое, не требует обучения |
| максимум оценок | нет | тот же результат, что среднее |
| средний ранг | нет | усложнение без выигрыша |
| стекинг | нет | модели коррелируют (0.74), честная мета-модель требует вложенной CV, на 40 группах слишком шумной |

### 3.5 Гиперпараметры

Сетка по тем же фолдам, критерий - partial AUC кривой TR - FA на FA ∈ [0, 1] (весь рабочий диапазон вместо одной шумной точки): CatBoost `depth` ∈ {4, 6, 8} × `iterations` ∈ {300, 1000}; лес `min_samples_leaf` ∈ {1, 5, 20} × `max_features` ∈ {`sqrt`, 0.5}. Лучший CatBoost - дефолтный. Лес с `min_samples_leaf = 5` лучше дефолтного по отдельности, но в ансамбле разницы нет (0.3725 против 0.3716 в среднем по трём seed). Итог - параметры по умолчанию. Вложенная CV не делалась, поэтому изменение принималось, только если выигрыш больше разброса от seed.

### 3.6 Эксперименты с признаками

Все варианты на одних фолдах, CatBoost, OOF:

| Набор | TR при FA ≤ 0.3 | TR при FA ≤ 1.0 | Решение |
|---|---|---|---|
| baseline-правило | 0.186 | 0.388 | планка |
| сырые амплитуды 8 слотов | 0.153 | 0.301 | нет: хуже правила, модели приходится восстанавливать «максимум по соседям» и роль расстояния из отдельных слотов |
| станционные (11), без весов | 0.311 | 0.443 | основной прирост |
| **станционные (11), веса случаев** | **0.317** | **0.486** | **итоговый набор** |
| + сырые слоты | 0.235 | 0.459 | нет |
| + история случая (максимум с начала, изменения за 1-2 с, скользящее среднее) | 0.273 | 0.388 | нет: хуже перенос на M7.1, в рое афтершоков у отрицательных тоже высокий максимум с начала |
| + пространственные (интерполяция амплитуды в точку цели, наклон затухания) | 0.279 | 0.514 | нет: в пределах шума |

### 3.7 Финальное обучение

`Model.fit` воспроизводит весь протокол на train: строит группы и фолды, считает признаки, цель строк и веса, получает OOF-оценки ансамбля, выбирает по ним порог при FA ≤ 0.5, затем обучает обе модели на всём train. `update(candidate_id, row)` считает признаки строки, усредняет вероятности двух моделей и возвращает максимум оценки с начала случая: момент первого пересечения порога от этого не меняется, а выход монотонный. История каждого случая хранится отдельно по `candidate_id`, `reset` её очищает, `save` / `load` пишут систему вместе с порогом в один файл через `joblib`.

## 4. Validation

### 4.1 Протокол

Каждый случай train получает оценку от модели, которая не видела его группу. Метрики и порог считаются по объединённым OOF-оценкам: TR по 183 случаям «можно успеть», FA - ложные предупреждения в потоке train на 97.5 станцио-часа. Усреднение метрик по фолдам не используется: в маленьких фолдах один случай меняет TR на 5-10 п.п., а порог в системе один.

Контроль того, что протокол действительно отделяет обучение от проверки: модель, обученная и оценённая на потоке train, даёт TR 1.0 при FA 0.02, а OOF-оценка той же системы - 0.43 при FA 0.49.

### 4.2 Сравнение моделей

Все модели сравниваются в одинаковых условиях: те же признаки, веса, фолды и подсчёт метрик по OOF-оценкам.

*Рисунок 1. TR от FA при переборе порога для правила, отдельных моделей и ансамбля, OOF train. Пунктир - бюджет 0.5.*

| Модель | TR при FA ≤ 0.3 | TR при FA ≤ 0.5 | TR при FA ≤ 1.0 | partial AUC (FA 0-1) |
|---|---|---|---|---|
| baseline-правило | 0.186 | 0.284 | 0.388 | - |
| CatBoost | 0.317 | 0.388 | 0.486 | 0.365 |
| случайный лес | 0.317 | 0.350 | 0.410 | 0.335 |
| **ансамбль** | 0.290 | **0.426** | 0.486 | **0.378** |

Обе модели лучше правила на участке FA примерно от 0.05 до 1.2, где лежит рабочая точка. Выше 1.3 правило не хуже: когда ложная тревога почти ничего не стоит, выгоднее реагировать на любую сильную амплитуду у соседа. Ансамбль в рабочей точке лучше обеих базовых моделей (78 своевременных против 71 и 64) и имеет наибольший partial AUC, но разница с CatBoost в пределах шума. При FA ≤ 0.3 модели вместе ловят 44 общих случая и ещё по 14 уникальных, но каждая приносит и свои ложные тревоги, поэтому объединение добавляет мало. Ансамбль выбран как не уступающий лучшей модели в рабочей точке; основной вклад в качество дают признаки.

## 5. Test

### 5.1 Протокол

Test запущен один раз для зафиксированной системы; после прогона система не менялась. `run_experiment.py` обучает и сохраняет модель, загружает её из файла и воспроизводит `continuous_test_stream.csv` по сообщениям: `window_start` вызывает `reset`, `observation` - один `update`. Таблица предупреждений (`episode_id`, `t_sec` первого достижения порога) сохраняется в `results/alarms_continuous_test_stream.csv`, 71 строка. Событийный test подаётся строками в `update` в порядке `t_sec` внутри случая. Из-за малого числа случаев TR приводится как `k из n` с интервалом Вильсона.

### 5.2 Результаты

| Часть | Своевременных / можно успеть | TR | Поздних | Пропусков | Ложные | Медиана запаса, с |
|---|---|---|---|---|---|---|
| поток | 8 / 15 | 0.533 | 4 | 3 | 0.508 на станцио-час (49 на 96.5) | 4.1 |
| события | 5 / 6 | 0.833 | 1 | 0 | 18.8% отрицательных (19 из 101) | 5.1 |
| вместе | 13 / 21 | 0.619 (95% ДИ 0.41-0.79) | 5 | 3 | - | - |

System recall с учётом слепой зоны - 13 из 47 (0.28): 26 из 47 положительных test имеют `T < 3`, этот показатель ограничен физикой и с train не сравним.

### 5.3 Сравнение с validation

| Показатель | Validation (OOF) | Test |
|---|---|---|
| FA потока, на станцио-час | 0.49 | 0.508 |
| TR, все | 0.43 (78 / 183) | 0.62 (13 / 21) |
| TR при `T` 3-6 с | 0.41 (22 / 54) | 0.63 (12 / 19) |
| медиана запаса, с | 7.7 | 4.1-5.1 |
| доля ложных в событиях | 11.6% | 18.8% |

FA на test совпала с оценкой validation, хотя отрицательных случаев на станцио-час на test в 2.4 раза меньше: порог, выбранный по OOF, перенёсся без сдвига. TR на test выше, но интервал широкий (один случай меняет TR на 4.8 п.п.), и оценки по быстрым случаям совместимы. Меньший запас объясняется составом test: почти все случаи с `T < 6`, главного толчка нет.

### 5.4 Примеры ошибок

Характеристики соседей в последнюю секунду, когда предупреждение ещё было бы своевременным, поток test:

| Исход | `T`, с | Дедлайн `t` | Тревога | Оценка к дедлайну | Что видно у соседей к дедлайну |
|---|---|---|---|---|---|
| пропуск | 3.24 | 0 | нет | 0.45 | максимум 0.006 g, выше 0.001 g один сосед |
| пропуск | 4.27 | 1 | нет | 0.15 | максимум 0.029 g, выше 0.001 g один сосед |
| пропуск | 4.11 | 1 | нет | 0.49 | максимум 0.052 g, выше 0.001 g четыре соседа |
| позднее | 3.62 | 0 | 9 | 0.01 | максимум 0.002 g, выше 0.001 g один сосед |
| позднее | 5.03 | 2 | 10 | 0.49 | максимум 0.003 g, выше 0.001 g четыре соседа |

Ошибки того же типа, что на validation: в большинстве случаев к дедлайну сработал один сосед со слабой амплитудой. Два случая с оценкой 0.49 близки к порогу 0.56 и были бы пойманы при большем бюджете ложных. 57% ложных тревог потока отправлены на `t = 0`, когда случай открывается сразу сильной амплитудой у соседа, а до цели тряска не доходит. Среди 46 случаев с недоступной станцией только один «можно успеть» (не пойман), ложных 7 из 35 отрицательных против 42 из 290 без пропуска; отдельной надёжной оценки по ним нет.

## 6. Применение и мониторинг

### 6.1 Потоковый режим и задержка

| Параметр | Значение |
|---|---|
| что измерено | `model.update`: признаки строки, `predict_proba` двух моделей, обновление состояния случая; чтение файла не входит |
| вызовов | 11 129 (поток test) |
| медиана / p95 / максимум | 2.74 / 2.92 / 10.3 мс |
| условия | macOS 26.6.2, Apple Silicon, 8 ядер, Python 3.13.5, один процесс, лес с `n_jobs = 1` |

Задержка в сотни раз меньше шага данных в 1 с и на своевременность не влияет.

### 6.2 Мониторинг и переобучение

| Что отслеживать | Условие переобучения |
|---|---|
| ложные предупреждения на станцио-час | устойчиво выше бюджета 0.5 примерно вдвое |
| TR и запас по мере поступления ответов целевых станций | TR на новых случаях ниже интервала, полученного на test |
| входные данные: амплитуды соседей, частота срабатываний, доля недоступных станций | заметный сдвиг распределений |
| состав и положение станций сети | любое изменение: признаки построены на геометрии сети |
| число новых сильных событий | накопилось ещё 20-30 случаев «можно успеть» |
| время обработки строки | рост до десятков миллисекунд |

Переобучение выполняется тем же `Model.fit` (группы по землетрясениям, CV, порог по OOF), новую версию перед заменой сравнивают с текущей на самых поздних событиях.

## 7. Выводы

Система - мягкое голосование CatBoost и случайного леса на 11 признаках силы тряски у соседей с учётом расстояния до цели, порог выбран по OOF-оценкам при бюджете 0.5 ложных тревог на станцио-час. На hold-out она вовремя предупреждает в 13 из 21 случая, где это возможно (0.62, 95% ДИ 0.41-0.79), при 0.51 ложных на станцио-час и запасе 4-5 с. На validation - 78 из 183 при 0.49 ложных; правило без обучения при том же бюджете ловит 52, то есть система лучше примерно в полтора раза. Частота ложных тревог, по которой выбирался порог, подтвердилась на test без сдвига, это главный аргумент в пользу схемы проверки.

Основной прирост дали признаки по станциям с учётом расстояния и веса случаев. Выбор между моделями и способ их объединения влияют меньше, чем разброс от seed. Потолок качества задают данные: значительная часть быстрых случаев к дедлайну неотличима от отрицательных.

| Ограничение | Последствие |
|---|---|
| 40 независимых групп, одна (M7.1) даёт 58% положительных train | шум сравнения около ±10 случаев, тонкие улучшения не измеряются |
| test - 21 случай почти только с `T < 6` | широкий интервал TR, нет оценки на сильном землетрясении вне train |
| отдельная проверка forward chaining по времени не выполнялась | перенос во времени подтверждён только test и фолдом M7.1 |
| в train нет недоступных станций | работа при пропусках оценена только имитацией |

Рабочая точка зависит от применения: 0.5 ложных на станцио-час рассчитана на дешёвые автоматические действия, для публичного оповещения нужна точка около 0.1 на той же кривой, где TR около 0.18. Наибольший потенциал роста - не модель, а данные: больше сильных землетрясений в обучении.
