# ЛР 3. KNN: метод ближайших соседей

## Задача

На дворе 2036 год. Оперативка стоит больше золота, новенькую GPU можно получить только
в обмен на 100 баррелей нефти.
Вы работаете в маркетплейсе, у которого вот уже 10 лет проблемы с финансами.
Руководство больше не готово на каждый чих арендовать дорогое железо, и хочет попробовать
заменить одну из внутренних моделей на модель KNN.

Вы работаете с карточками товаров маркетплейса. Для обработки элементов карточки
(текст, изображения, история модерации) всё ещё используются сложные нейросети. 
Топ-менеджмент был убежден, что без этого хорошо анализировать карточки не получится.
Однако топ-менеджмент знает, что результат работы большинства нейросетей — это
эмбеддинги — способ перевода слов, картинок или звуков в длинные списки чисел,
которые отражают их реальный смысл.

Вам предложили использовать метод ближайших соседей,
чтобы предсказывать экспертную оценку качества новой карточки 
по эмбеддингам, полученным из картинки, описания и прочего содержимого карточки.

Вам предоставили описание оценок
```text
0 = карточка очень низкого качества
1 = карточка низкого качества
2 = карточка приемлемого качества
3 = карточка хорошего качества
4 = карточка отличного качества
```
Но описывать, какие числа в данных отвечают за картинку, какие за текст, вам не хотят.
Просто вектор из 160 чисел на карточку товара...

Координаты векторов поступают из разных источников и не обязательно одинаково
информативны, надёжны или сопоставимы по масштабу. Задача — получить качественное
предсказание, быстрый `predict` и компактный файл модели.

Ваше решение должно оставаться одним KNN. Можно использовать готовую реализацию
или написать свою. Вы самостоятельно выбираете число соседей, метрику расстояния,
веса, способ агрегации и подготовку признаков.

## Данные

Исходная обучающая выборка содержит 15 000 объектов, тестовая — 3 000 объектов,
валидационная — 3 000 объектов.

У каждого объекта 160 числовых признаков: `x_000`, ..., `x_159`.
В обучающей выборке также есть столбец `target` с классом 0–4.

Вам предоставлена обучающая и тестовая выборка, а валидационная будет
использоваться вместе с тестовой на финальной проверке вашего решения.
На финальной проверке нужно предсказать ответы для 6 000 объектов одним вызовом.


## Что разрешено

- Готовые реализации KNN и библиотеки из фиксированного окружения задания:
  NumPy, pandas, SciPy, scikit-learn, joblib, Matplotlib и statsmodels.
- Выбор метрики расстояния и параметров KNN.
- Приближённый поиск ближайших соседей.
- Предобработка признаков.

Решение проверяется на CPU в одинаковых вычислительных условиях в одном потоке.

## Шаблон решения и запуск

В `model.py` реализуйте класс `Model`:

- `fit(X, y)` — обучение модели и предобработки.
- `predict(X)` — готовые классы в порядке входных строк.
- `save(path)` — сохранение всего обученного состояния в один файл.
- `Model.load(path)` — загрузка модели из этого файла.

`X` — `pandas.DataFrame` с именами колонок `x_000`, ..., `x_159`,
`y` — `pandas.Series` с классами. Предобработка новых данных входит в `predict`.
Можно добавить собственные Python-модули.

Методы `save` и `load` получают путь к одному файлу модели KNN, а не к
директории. Формат сериализации и расширение файла выбираете вы.
Размер готового файла модели не должен превышать 200 МБ.

Проверяющая программа напрямую вызывает интерфейс `Model`.
Заранее обученную модель в репозиторий сдавать не нужно. Окружение одинаково для
всех решений; `requirements.txt` зафиксирован в шаблоне и изменять его нельзя.

Простой рабочий пример — `model.py.example`. Чтобы запустить его, скопируйте
его в `model.py`; scikit-learn уже установлен в фиксированном окружении.
`predict` должен вернуть одномерный массив или список: по одному ответу на каждый
входной объект в исходном порядке. Допустимы только целочисленные классы от 0 до 4.

Обучение и предсказание должны быть детерминированными. При одинаковых обучающих
данных, параметрах модели и входных признаках решение должно возвращать в точности
одинаковые классы при каждом запуске. Если используемый алгоритм содержит
случайность, явно зафиксируйте `random_state` или seed.

## Оценивание

Максимальная итоговая оценка — 100 баллов:

- 46 баллов при эталонном качестве по MAE.
- 26 баллов при эталонном размере одного файла модели KNN.
- 26 баллов при эталонном времени вычисления `predict`.

Для всех трёх показателей меньше — лучше. MAE — средняя абсолютная ошибка:

```text
MAE = mean(abs(predicted_class - true_class))
```

Пороги, ограничения и формулы будут опубликованы позже.

Баллы за MAE рассчитываются по линейной шкале и продолжают расти выше 46 при
результате лучше эталонного. Баллы за размер и время обратно
пропорциональны показателю: уменьшение файла или времени в 2 раза даёт в 2 раза
больше баллов за соответствующую часть. За размер и время можно получить больше
26 баллов: улучшение одного ресурса может компенсировать недобор за другой.
Эталонная MAE и оба эталонных ресурса дают 98 баллов; до 100 можно добрать
улучшением любого из трёх показателей.
При неприемлемой MAE баллы за время и размер модели не начисляются.
Итог ограничен 100 баллами; сами показатели остаются видимыми и при достижении/превышении
эталонных значений.

Время `predict` — от получения признаков до готовых меток, включая необходимую
предобработку, но без загрузки модели, чтения и записи CSV.

> **Аварийные ограничения.** Контейнеру доступно не более 1 ГБ памяти. Обучение
> и сохранение модели должны завершиться за 60 секунд, как и этап, включающий
> загрузку, прогрев и предсказание. Превышение этих ограничений считается
> ошибкой решения. Ограничения не участвуют в начислении ресурсных баллов.

## Проверка через бота

Откройте `/knn` или кнопку «Проверка ЛР 3» в списке принятых заданий.
Проверка запускается по вашему запросу через Telegram-бота, не автоматически
по push. Доступно 7 проверок за календарные сутки, сброс в 00:00 по Москве.
Попытка списывается при принятии заявки; ошибка решения учитывается,
при сбое проверяющего сервиса попытка возвращается.
Можно отправить несколько заявок в очередь.
Каждая проверяет последний коммит сдаваемой ветки на момент принятия заявки;
новые push не меняют уже принятые заявки. Результат приходит в боте.

Финальный коммит нужно выбрать в боте среди успешно проверенных. Выбор можно
изменить до закрытия приёма. Если ручной выбор не сделан, используется последний
успешно проверенный коммит. Выбранный коммит будет использован для финальной
проверки на объединённой выборке `test + val`.
